## 1. 课题定义

### 1.1 一句话概括

> **训练一个小语言模型（Qwen3-4B 为主），让它做题时自己学会"什么时候调用 Python 代码工具"，并用强化学习（RL）把这种策略性工具使用越练越好；最终验证：原论文在 Qwen2.5-32B 上成功的 ReTool 方法，迁移到小模型上效果如何、训练稳不稳定、哪个 RL 算法最扛得住。**

### 1.2 核心 Research Question（RQ）

| 编号 | 问题 | 类型 |
|---|---|---|
| **RQ1** | ReTool 式 agentic RL（SFT + 工具增强 RL）能否提升小模型（4B/1.7B）的数学推理能力？在 AIME/MATH 上相对纯文本基线的增益是多少？ | 主线 |
| **RQ2** | 同样设置下，DAPO vs GRPO vs PPO 在小模型上谁的效果最好、训练最稳定？（熵坍塌、收敛速度、最终分数） | 主线 |
| RQ3 | 工具使用是否带来效率收益？（回答长度、token 消耗、调用次数/成功率 vs 纯文本） | 必做分析 |
| RQ4（扩展） | 去掉 SFT / 去掉代码工具，方法还 work 吗？（消融） | 扩展 |
| RQ5（扩展） | 训练分布之外的数学基准上泛化掉多少？（OOD） | 扩展 |
| RQ6（扩展） | 会不会奖励黑客 / 工具过度调用？鲁棒性如何？ | 扩展 |

### 1.3 预期假设（写下你的预测，论文的"故事线"）

1. 小模型上 agentic RL 会**有效但增益小于大模型**（原论文 AIME 提升 ~27 点），因为小模型容量限制了复杂工具策略的习得。
2. **DAPO 最稳**（其动态采样/clip-higher 专治小模型常见的熵坍塌与奖励噪声）；GRPO 次之；PPO 在小模型 + 长回答上最不稳定。
3. 工具使用会**缩短有效回答长度**（小模型上效果待验证）。
4. SFT 阶段可能**不可省略**（小模型不会自己发明工具调用格式，需要先学会格式）。

### 1.4 创新点 / 贡献（相对原论文）

- **迁移研究**：ReTool 原论文只做了 32B 级别，本项目系统评估 1.7B/4B 小模型上的迁移表现。
- **受控算法对比**：同一设置下对比 DAPO / GRPO / PPO（原论文只用 PPO）。
- **小模型稳定性分析**：量化熵坍塌、格式崩溃、奖励噪声在小模型上的表现与对策。
- **工具使用行为学分析**：调用时机、频率、纠错行为的涌现观察（小模型版本）。

## 2. 核心概念速查（从零到跑通）

> 全部用"学生做题"类比。**首次阅读记住每行一句话即可**，随着实验推进逐步加深。

### 2.1 LLM 训练的三种方式

| 概念 | 一句话 | 类比 | 在本项目中的角色 |
|---|---|---|---|
| 预训练 pre-training | 在海量文本上学语言规律，产出 base model | 婴儿学说话 | 我们**不碰**，直接用现成 base |
| SFT 监督微调 | 看"题目→标准解答"例子，模仿 | 老师给标准答案背书 | **Phase 2**：让模型学会工具调用格式 |
| RL 强化学习 | 只给"对/错打分"，模型自己摸索策略 | 只判分不给答案 | **Phase 3**：学会"何时用工具、如何纠错" |

### 2.2 RL 术语

| 术语 | 一句话 | 说明 |
|---|---|---|
| Policy（策略） | 模型本身，`policy(题目) → 回答` | 训练目标就是让策略变好 |
| Rollout（采样） | 模型做一题的完整生成过程 | RL 的"样本" |
| Reward（奖励） | 判分：答案对 +1 / 错 0 / 无答案 -1 | 用规则判定，**不需要奖励模型** |
| RLVR | 可验证奖励的 RL | 数学/代码类任务专用，你的课题正属此类 |
| PPO | 经典 RL 算法，裁剪更新幅度防崩 | 需要价值网络（critic），吃显存 |
| GRPO | PPO 简化版，组内相对好坏算优势，砍掉 critic | DeepSeek-R1 带火；省显存 |
| DAPO | GRPO 升级版，修熵坍塌/奖励噪声/长回答问题 | **本项目首选算法** |
| KL penalty | 限制新策略别离旧策略太远 | 防过拟合/防崩 |
| 熵坍塌 entropy collapse | 模型过早失去多样性，反复输出同一种话 | DAPO 的 clip-higher 专治此病 |
| 奖励黑客 reward hacking | 模型找奖励的漏洞（如刷格式、胡写工具调用） | 需要监控工具调用分布 |
| pass@1 | 一次采样答对的概率 | 本项目所有评测指标 |

### 2.3 Agentic / Tool-use 术语

| 术语 | 一句话 |
|---|---|
| Agentic RL | RL 中模型不止生成文字，还能与环境交互（调工具） |
| Tool use / code interpreter | 工具 = Python 代码解释器（沙箱里执行，安全隔离） |
| Sandbox（沙箱） | 执行模型代码的隔离环境（SandboxFusion 或 docker） |
| Multi-turn rollout | 一轮训练样本里模型可多次调工具、多次收到结果 |
| Agent loop | 训练框架里"模型↔工具"来回循环的调度逻辑（verl 的 AgentLoop） |
| `\boxed{答案}` | 数学题输出格式，奖励函数靠它提取答案 |

### 2.4 评测基准

| 基准 | 内容 | 难度 | 用于 |
|---|---|---|---|
| AIME 2024 / 2025 | 美国数学邀请赛（各 30 题） | 竞赛级 | 主线指标（与 ReTool 论文对齐） |
| MATH-500 | MATH 抽样 500 题 | 中高 | 泛化/补充指标 |
| GSM8K | 小学级文字题 | 低 | 能力下界参考 |
| AMC（可选） | 美国数学竞赛 | 中高 | OOD 扩展 |

## 4. 资源规划（HKUST SuperPOD H800）

### 4.1 硬件含义

- H800：80GB HBM，单节点 8 卡。**Qwen3-4B 单节点（8×H800）即可舒适训练**。
- SuperPOD 为多节点集群 → verl 的 Ray + FSDP + vLLM 正是为此设计，多节点可扩展。
- 注意点：H800 NVLink 带宽低于 H100（约一半），**跨节点 FSDP 通信是潜在瓶颈**，所以优先单节点内扩展，必要时才跨节点。

### 4.2 建议作业形状（以 4B 主实验为例）

| 参数 | 建议值 | 备注 |
|---|---|---|
| 节点数 | 1 节点（8×H800）起步 | 不够再加 |
| 模型 | Qwen3-4B（RL 前 = SFT 后 checkpoint） | |
| GRPO 组大小 G | 8（可试 16） | 越大越稳但越贵 |
| max tokens | 16k~24k | 长回答需要 |
| 训练步数 | 400~1000 | 参照 ReTool 的 400 步收敛 |

### 4.3 集群使用注意事项

- 先向管理员确认**配额/排队机制**、单次作业最长时长、是否按卡时计费。
- 共享集群上**别在高峰时段开大作业**；小规模调参用 1.7B，正式实验再上 4B。
- 提前写好**可断点续训**（checkpoint + 恢复）配置，避免排队/中断返工。

## 5. 六阶段任务书

> 每阶段含：目标 / 任务清单（带小时预算）/ 产出 / 验收标准 / 常见坑。
> 总预算：P0(28h) + P1(15h) + P2(15h) + P3(48h) + P4(25h) + P5(30h) = **161h** + 缓冲 19h ≈ 180h。

### Phase 0：基础学习 + 环境打通（第 1–2 周，~28h）｜🔴 不可跳

**目标**：能复述 ReTool 方法；verl 最小管线跑通。

| 任务 | 时间 |
|---|---|
| 精读 ReTool 论文（Abstract+方法+实验），写 1 页中文总结 | 6h |
| 通读 verl-recipe/retool 目录结构，标出每个脚本在管线中的位置 | 4h |
| HF 工具链上手：datasets/tokenizer/transformers 基础 + 用本地 Qwen 做一次推理 | 5h |
| 申请 SuperPOD 账号、装 verl 及其依赖（vLLM/Ray/FlashAttn/SandboxFusion） | 6h |
| **最小管线验证**：Qwen3-1.7B 把 retool recipe 跑通（哪怕 5 步 RL），确认工具真能被调用 | 7h |

**产出**：论文理解笔记；环境可复现的安装清单；第一条训练曲线 + 一个含工具调用的 rollout 样本。
**验收**：① 能向同学讲清"三阶段"；② `verl` 最小流程完整跑完；③ 能答出"我的一个 rollout 样本长什么样"。
**常见坑**：verl 版本与 recipe 不匹配（按 recipe 锁版本）；flash-attn 编译失败（用预编译 wheel）；多轮 token 一致性 bug（用 recipe 默认实现，别自己改）。

### Phase 1：基座基线评估（第 3 周，~15h）｜🔴 对照组，质量决定一切

**目标**：得到干净、可复现的"未训练基座"分数表。

| 任务 | 时间 |
|---|---|
| 选定并固定评测脚本（ReTool 官方评估 或 lm-evaluation-harness，**全流程不换**） | 4h |
| 评测 Qwen3-4B 与 Qwen3-1.7B：AIME24/25、MATH-500、GSM8K（pass@1，参数全固定并记录） | 8h |
| 记录平均回答长度 / token 消耗（作为工具效率分析的基线） | 3h |

**产出**：基线表 `模型 | AIME24 | AIME25 | MATH-500 | GSM8K | 平均长度`。
**验收**：表中每个数字都能说清"脚本+参数+seed"；与公开数字对得上或能解释偏差。
**常见坑**：不同模型用不同采样设置（必须统一）；seed 未固定（必须记录）。

### Phase 2：ReTool-SFT（第 4 周，~15h）

**目标**：让模型学会"工具调用格式"，验证"会调但不聪明"。

| 任务 | 时间 |
|---|---|
| 检查 ReTool-SFT 数据格式（`<tool>` 标签、多轮结构），画 1 个样本的标注 | 3h |
| 跑 recipe 的 SFT 预处理 + 微调 | 9h |
| 用 Phase 1 同套评测测 SFT 模型；采样多轮工具样本确认格式正确 | 3h |

**产出**：SFT checkpoint；训练曲线（loss 收敛）；SFT 中间评测分数；格式正确的工具调用样本。
**验收**：能从 SFT 模型采样出"调用工具→获得结果→继续推理"的完整轨迹。
**核心洞察（写进论文）**：SFT 后模型"会调但调得笨"——**SFT 只解决会不会，不解决该不该**，这正是 RL 阶段的意义。

### Phase 3：RL 训练（第 5–8 周，~48h）｜🔴 主战场

**目标**：DAPO 主实验 + GRPO 对比，得到训练曲线与最终 benchmark。

| 任务 | 时间 |
|---|---|
| 配置奖励函数（Math-Verify 判 `\boxed{}`）+ 沙箱 + agent loop | 6h |
| 1.7B 冒烟测试：50 步内看曲线是否上升、工具调用是否正常 | 6h |
| **DAPO 主实验**：Qwen3-4B 全量训练（400~1000 步，多轮监控） | 18h |
| **GRPO 对比实验**（config 级切换，成本低） | 10h |
| （可选）PPO 对比实验（需价值网络，显存吃紧） | 8h |
| 全程记录：reward / 准确率 / 回答长度 / 工具调用频率与成功率 / KL / 熵 | 与上并行 |

**产出**：三条训练曲线；各算法最终分数表；工具行为随时间变化图。
**验收**：① 曲线明显上升；② 三算法**完全同设置**对比；③ 能采样出"推理→调代码→报错→纠错→出答案"轨迹。
**常见坑**：reward hacking（监控工具调用次数分布）；长上下文 OOM（降 batch/max tokens）；熵坍塌（DAPO 专治，但设置要正确）。

### Phase 4：分析与扩展（第 9–10 周，~25h）

**目标**：把"复现"升级成"科研结论"。

| 任务 | 时间 | 必做? |
|---|---|---|
| 定性样例分析：基线 vs SFT vs RL 的 5–10 题轨迹对比 | 6h | ✅ 必做 |
| 工具使用效率分析：调用次数/成功率/纠错轮次/节省 token | 5h | ✅ 必做 |
| 消融或 OOD 选其一：无 SFT 直接 RL，或换基准测泛化 | 8h | ⚠️ 至少 1 个 |
| 鲁棒性检查：奖励黑客审计、工具过度调用统计 | 6h | ⚠️ 尽量 |

**验收**：每个实验都有"一张表/一张图 + 一句为什么这么设计"。
**提示**：工具效率分析几乎零成本——rollout 日志里本来就有工具调用记录，只是需要写脚本统计。

### Phase 5：写作与汇报（第 11–12 周，~30h）

**目标**：产出完整的 IP 项目报告 + 可复现包。

| 任务 | 时间 |
|---|---|
| 报告主体：背景 / 方法 / 实验设置 | 10h |
| 结果章节：benchmark 表、训练曲线、样例分析、算法对比结论 | 12h |
| 可复现包：config、数据版本、随机种子、评测脚本清单 + README | 5h |
| 校对与格式（HKUST IP 提交要求） | 3h |

**产出**：最终报告 + 可复现性材料包。
