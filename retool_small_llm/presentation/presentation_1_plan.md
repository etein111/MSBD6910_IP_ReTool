### A.3 排期解耦与协作结构

#### A.3.1 解耦原则

排期耦合的来源是需要**在时间上同步的决策**。解耦的方法是将这类决策事前写成规则并一次发布，由成员各自触发。

协作分为两类。**知识共享**为异步、可选：成员将方案发布到共享位置，其余成员在推进到该问题时自行决定是否采用，不产生排期耦合。**排期依赖**为同步、强制：成员必须等待他人产出才能继续，应予消除。

## C. 研究背景、研究意义与预期目标

> 本节针对成员 A 的研究问题展开：在 Qwen3-1.7B 上，ReTool 管线是否仍然带来准确率与效率增益，以及该增益对 RL 算法的敏感程度。

### C.1 研究背景

#### C.1.1 纯文本推理的结构性缺陷

思维链（Chain-of-Thought）显著提升了语言模型在数学推理任务上的表现。然而纯文本推理存在一项结构性缺陷：算术与符号运算的每一个中间步骤都由模型参数化的知识完成，缺少确定性的执行保障。在自回归生成过程中，单步计算错误会沿序列向后传播，而模型无法在单次回答内获得外部反馈来纠正该错误。这一缺陷在竞赛级数学任务上被进一步放大——AIME 等基准对中间步骤的精确性要求极高，任何一步笔算失误都会导致最终答案错误，且该错误与模型的推理思路质量无关。

#### C.1.2 工具集成推理的三代演进

针对上述缺陷，工具集成推理（Tool-Integrated Reasoning, TIR）逐步发展，可划分为三代。

**第一代是提示工程方法。** PoT（Program of Thoughts）与 PAL（Program-Aided Language Models）提示模型生成程序并交由解释器执行，将精确计算外包给确定性环境。此类方法不改变模型参数，其效果依赖提示设计，缺乏稳定性。

**第二代是监督微调方法。** MathCoder、ToRA、MAmmoTH 以及 Qwen2.5-Math-TIR 通过构造自然语言推理与代码交织的轨迹数据执行 SFT，使模型习得工具调用的格式与模式，能力显著优于纯提示方法。该方法存在明确上限：SFT 的学习信号完全来自数据分布，模型学到的是「在训练数据中频繁出现工具调用的位置进行调用」，而非「在当前这道题上何时调用工具才能提升正确率」。策略性工具使用（strategic tool use）未被优化目标直接约束。

**第三代是基于强化学习的方法。** Search-R1、ToRL 与 ReTool 将工具使用纳入 RL 框架，以任务结果驱动策略优化。其中 ReTool 在数学推理任务上取得了目前最显著的进展。

#### C.1.3 ReTool 的方法设计与实验结论

ReTool 的核心设计由三部分构成。其一是冷启动数据与 SFT 阶段：从经过双重过滤的纯文本推理数据集出发，将其中可受益于代码执行的笔算步骤改写为代码，经两阶段验证后得到代码增强轨迹集，用于监督微调，使模型习得工具调用的格式。其二是工具增强 RL 阶段：模型在沙箱中实时执行代码并接收执行结果或报错信息，形成多轮 rollout 轨迹。其三是奖励设计：奖励函数为规则化的、仅依据最终答案正确性的稀疏奖励，答案正确记为 +1，否则记为 −1。该设计的关键在于，工具是否被调用、代码是否可执行，均不产生任何奖励信号，沙箱返回的执行结果仅作为模型上下文存在。这一设计避免了「为代码可执行性给分」所诱发的奖励黑客行为。

ReTool 在 Qwen2.5-32B-Instruct 上的实验结果如下（AIME 2024）：

| 阶段 | AIME 2024 | 收敛步数 |
|---|---|---|
| 基座模型（无训练） | 26.7 | — |
| 加冷启动 SFT | 40.9 | — |
| 加工具增强 RL | 67.0 | 400 |
| 纯文本 RL 对照组 | 40.0 | 超过 1000 |

该结果包含两项具有结构性意义的观察。第一，工具单独（SFT 40.9）与 RL 单独（纯文本 RL 40.0）的效果接近，而两者的组合产生质变（67.0）。工具提供精确计算能力，RL 提供「何时使用工具」的策略，二者的增益是乘性关系而非加性关系。第二，ReTool 的收敛速度显著更快，所需训练步数不足纯文本 RL 的一半。

行为层面的证据进一步支撑「模型习得策略性工具使用」这一解释：回答长度下降约 40%，约 98% 的回答包含代码，平均代码行数增至约 5 倍，代码执行成功率在答对题目上接近 100%，且工具调用的位置随训练逐步提前。此外，ReTool 观察到 SFT 数据中未出现的代码自我纠错行为，即模型在收到报错后输出反思性文本并重写代码。

#### C.1.4 既有工作的边界

ReTool 的实验设计存在三项边界，构成本项目的切入点。

**规模边界。** 全部实验仅在 Qwen2.5-32B-Instruct 与 DeepSeek-R1-Distill-Qwen-32B 两个 32B 级基座上完成，未涉及更小规模。小模型方向上唯一已发表的尝试是 ToRL，其在 Qwen2.5-Math 1.5B 与 7B 上以 RL 学习工具使用，被 ReTool 论文判定为 *"the performance remained suboptimal"*。该判定提出了一项尚未解决的问题：ReTool 的增益是否依赖模型容量，抑或其管线设计本身即可在小模型上生效。

**算法边界。** ReTool 仅使用 PPO 一种 RL 算法。PPO 需要额外的价值网络，显存开销显著高于 critic-free 方法。在算力受限的小模型场景下，GRPO 及其改进版本 DAPO 是更现实的选择。然而这两种算法在 agentic 场景下的相对表现缺乏受控对比——现有的算法对比研究主要集中于纯文本推理场景，而 agentic 场景引入了多轮交互、稀疏奖励与外部工具三类额外方差来源，算法之间的相对表现在该场景下未必与纯文本场景一致。

**效率边界。** ReTool 报告了回答长度下降 40% 与收敛步数减少等效率收益，但该结果同样仅在 32B 上验证。小模型是否能够获得同等的效率收益，尚无证据。

#### C.1.5 工程约束

本项目受大学算力配额约束。Guideline 明确指出 *"University compute is limited"*，学生账号通常仅有有限的 GPU 小时配额，超出配额将导致运行中的作业被终止。该约束决定了本项目必须选择最小的可行模型并采用参数高效微调方法。值得注意的是，该约束本身也构成研究动机的一部分：若 ReTool 方法仅在 32B 级别成立，则其在真实学术算力条件下的可复现性值得独立检验。

### C.2 研究意义

#### C.2.1 方法层面：提供小模型 agentic RL 的受控算法对比

现有文献中，PPO、GRPO 与 DAPO 的对比主要发生在纯文本推理场景。Agentic 场景改变了问题的结构：多轮交互使奖励的信用分配跨越更长的序列，外部工具的引入使 rollout 方差不再仅来源于采样随机性，稀疏的结果奖励在小模型上更容易导致优势估计的退化。在此条件下，算法之间的相对表现需要独立验证。本项目在 Qwen3-1.7B 上固定基座、数据、沙箱、奖励函数与评测协议，仅改变 RL 更新方式，为「小模型 agentic RL 应选择何种算法」提供直接实验证据。

#### C.2.2 机理层面：量化模型容量对策略性工具使用的限制

ReTool 的消融结果显示工具与 RL 的增益呈乘性关系。若该乘性关系在 1.7B 上减弱，则表明策略性工具使用需要一定的模型容量作为支撑。本项目的贡献在于将该笼统判断分解为可观测的行为指标：通过 format rate、沙箱成功率、工具调用时机、自我纠错轮次等中间量，可以区分容量不足的具体表现形态——是格式习得失败、调用时机不当，还是纠错能力缺失。这一分解对后续小模型 agentic RL 的方法设计具有直接参考价值。

#### C.2.3 实践层面：检验方法在受限算力条件下的可复现性

ReTool 是目前数学推理方向上工具增强 RL 的代表性工作。其是否能被算力有限的研究者复现，直接决定该方法的实际影响范围。本项目在配额受限条件下完成复现，其结果对该问题具有直接的回答能力。

#### C.2.4 与直接竞品 ToRL 的关系

本项目与 ToRL 构成直接对话关系。若在 1.7B 上成功复现增益，则说明 ReTool 的管线设计——尤其是冷启动 SFT 阶段——是 ToRL 效果不佳的可能原因，从而为小模型 agentic RL 提供设计依据。若未能复现，则支持容量门槛假说，说明当前方法在 1.7B 规模上尚不适用。两种结果均具有明确的科学信息量。

### C.3 预期目标

#### C.3.1 总体目标

在 Qwen3-1.7B 上完成 ReTool 管线的端到端复现，并通过受控实验确定 GRPO 与 DAPO 在该规模、该场景下的相对稳定性。

#### C.3.2 具体目标

**目标一 · 建立冻结协议的基线。** 在 AIME 2024 与 2025 上，以每题 12 次采样的固定协议，测得不训练模型在 tool-enabled 与 text-only 两种模式下的 Average@N、Pass@N、format rate 与工具使用统计，并记录定性轨迹。

**目标二 · 复现 SFT→RL 增益。** 在 1.7B 上得到 base → +SFT → +RL 的三段曲线，并与 ReTool 在 32B 上的 26.7 → 40.9 → 67.0 做规模对照。

**目标三 · 完成算法对比。** 在完全相同的基座、数据、沙箱、奖励与评测设置下，以相同的训练步预算运行 DAPO 与 GRPO，给出最终 AIME 分数与训练稳定性指标（reward、entropy、退化组比例、回答长度）。

**目标四 · 给出机理解释。** 量化工具使用行为随训练的演变过程，并审计是否存在奖励黑客现象。

#### C.3.3 预期结果

任何一项假设被证伪均不构成项目失败。

| 假设 | 若成立 | 若被证伪 |
|---|---|---|
| H1 | 支持「SFT 解决会不会、RL 解决该不该」的分工，SFT 的作用集中于格式习得 | 表明小模型的瓶颈不在格式习得而在策略优化，该结论本身即为有价值的发现 |
| H2 | 支持容量门槛假说，说明策略性工具使用需要一定的模型容量 | 表明 ReTool 方法在小模型上同样有效，方法的适用范围得以扩展 |
| H3 | 在相同训练预算下，critic-free 方法之间存在可观测的稳定性差异，为算法选择提供依据 | 表明两种算法在小模型 agentic 场景下表现一致，该一致性本身具有参考价值 |
| H4 | 修正「工具使用必然缩短回答」的简化描述，给出更精确的长度演化规律 | 表明小模型的工具使用行为与 32B 一致，长度缩短是方法层面的稳定特征 |

## I. 核心表述

1. ReTool 在 32B 规模上验证了工具与 RL 的乘性增益（26.7 → 40.9 → 67.0），但其实验仅覆盖单一规模与单一算法（PPO），而小模型方向上唯一的已发表尝试（ToRL）被判定为 suboptimal。

2. 本项目的切片是：在 Qwen3-1.7B 上完成 base → SFT → RL 的完整复现，在基座、数据、沙箱、奖励与评测全部冻结的条件下，仅改变 RL 更新方式，在相同的训练步预算下完成 GRPO 与 DAPO 的受控对比。队友分别在 2B 与 4B 上承担 SFT 必要性消融与工具变量对照。三人合并后构成「规模 × 算法 × SFT 必要性 × 工具变量」的完整论证。

3. 交付物不限于分数表，还包括训练稳定性与小模型工具行为的分析，这两部分正是原论文未覆盖的内容。
